## 작성 규칙

- 아이디어 하나에 파일 하나. 파일명은 영문 kebab-case (`project-museum-site.md`).
- 사용자가 말한 내용과 에이전트가 덧붙인 제안을 구분해서 적는다. 사용자가 말하지 않은 것은 "미정" 또는 "제안"으로 표시한다.
- 파일을 추가하거나 상태가 바뀌면 위 목록을 갱신한다.

## 박물관 전시

박물관(`projects/museum`)이 빌드할 때 이 폴더를 읽는다. 상태가 아이디어·보류·구현 중인 것은 "준비 중"으로 걸리고, 완료·폐기는 걸리지 않는다(완료된 것은 프로젝트 저장소의 `deploy/exhibit.json`으로 걸린다). 박물관 자신도 다른 프로젝트처럼 `deploy/exhibit.json`으로 걸린다. 위 형식의 선택 항목은 박물관 화면에만 쓴다.

## 상태 값

- **아이디어**: 적어만 둔 상태
- **보류**: 하기로 했지만 지금은 아님
- **구현 중**: 저장소를 만들고 서브모듈로 연결함
- **완료**: 동작하는 결과물이 있음
- **폐기**: 하지 않기로 함

## 파일 형식

```markdown
# 제목

- 상태: 아이디어
- 작성일: YYYY-MM-DD
- 저장소: (구현 시작 후 링크)
- 전시 제목: (선택) 박물관에 걸 짧은 제목. 없으면 맨 위 제목
- 전시 설명: (선택) 박물관에 걸 한두 문장. 없으면 "개요"의 첫 문단
- 영어 제목: (선택) 박물관 영어 화면의 제목
- 영어 설명: (선택) 박물관 영어 화면의 설명
- 출처: (선택) 방문자 아이디어에서 왔으면 vive-museum#번호

## 개요
## 요구사항
## 미정 사항
## 메모
```
